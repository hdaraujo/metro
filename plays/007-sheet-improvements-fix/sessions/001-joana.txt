  ⎿ # Chrome on Android Edge-to-Edge: Key Behaviors
  ⎿ 
  ⎿ ## Content Drawing Under Navigation Bar
  ⎿ 
  ⎿ From Chrome 135 onward, the viewport extends into Android's gesture navigation bar. By default, a dynamic "chin" appears over this area that retracts during scrolling. The document states: *"From Chrome 135, the viewport is allowed to extend into Android's gesture navigation bar."*
  ⎿ 
  ⎿ When the chin retracts, content can become obscured. The guide notes: *"When the chin is present, the content will initially be reachable by users but will get obstructed by Android's navigation bar as the chin goes away."*
  ⎿ 
  ⎿ ## Safe Area Inset Reporting
  ⎿ 
  ⎿ The `safe-area-inset-bottom` environment variable dynamically updates as the chin moves. It represents *"a rectangle by its top, right, bottom, and left insets from the edge of the viewport."* The value changes in real-time to keep content above the navigation bar.
  ⎿ 
  ⎿ Additionally, Chrome 135 introduces `safe-area-max-inset-bottom`, which represents *"the maximum value of the safe-area-inset-bottom"* and remains static.
  ⎿ 
  ⎿ ## Viewport-Fit=Cover Behavior
  ⎿ 
  ⎿ Websites can opt into edge-to-edge by default using `viewport-fit=cover` in the viewport meta tag. The guide explains: *"When enabled, the viewport will extend up to the bottom edge by default without the chin ever being visible."*
  ⎿ 
  ⎿ Without this setting, the chin appears by default.

● I've made a fix on a new branch, `007-sheet-improvements-fix`, but I couldn't test it on a Redmi 15C, so please check it on the phone. Nothing is committed yet.

**Cause:** the sheet always has room for 4 rows, on every screen size. The problem is that the app told the browser it could draw behind the phone's system bars (`viewport-fit=cover`). It then relied on the phone reporting how tall the navigation bar is (`env(safe-area-inset-bottom)`) so it could keep the sheet above it. If a phone reports 0 but still covers the bottom of the page, the 4th row ends up under the navigation bar. The sheet and the bar are both white, so it looks like the list just ends after 3 rows. The installed app on newer Android versions draws edge to edge, which fits that. This is my best explanation, not something I confirmed on the device.

**Fix:**
- **`index.html`:** removed `viewport-fit=cover`. Android now keeps the page above its system bars itself, so it doesn't matter what an individual phone reports. That's what makes it work on any phone.
- **`src/ui/styles/app.css`:** the page background is now white instead of the map colour. Any strip the browser leaves below the sheet (for example the iPhone home-bar area) now matches the sheet instead of showing a beige band.
- **`tests/e2e/map.spec.ts`:** added a phone test that fails if `viewport-fit=cover` is added back.

Lint, typecheck, the unit tests and the end-to-end tests all pass. The tests can't simulate a navigation bar covering the page, though.

**To check on the Redmi:** once it's deployed, the installed app picks up the new version in the background, so close and reopen it once or twice. You should see 4 rows, and the sheet should end just above the navigation bar. If it still shows only 3, send me a screenshot and I'll look for another cause.
