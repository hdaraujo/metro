**What the play asks for:** a base app with project scaffolding, a README, a `.gitignore` and dependencies. Its one feature is a map centred on the user's location, zoomed to show the nearest stop, and possibly the nearest bus too.

**How it lines up with the existing documents:**
- **Vision:** it matches "opens straight onto a map showing where you are, your nearest Metrobus stop". It also fits the Glanceable, Location-aware and Mobile-first principles, and it touches none of the non-goals.
- **Tech stack:** the scaffolding it needs is already described. That is the npm-workspaces layout (`apps/api`, `apps/web`, `packages/shared`), React + Vite + `vite-plugin-pwa`, MapLibre on OpenStreetMap tiles with attribution, and the browser Geolocation API. The play needs no new technology, repository or goal.

**Notes for the Planner:**
- Stops must come from `apps/api` through the Metro Mondego `stops.json` adapter. The web app never fetches the source directly.
- The nearest-stop logic belongs in `packages/shared` and needs Vitest unit tests.
- Showing the nearest bus is optional in the intent. If it is included, the bus position is an estimate from the timetable, not live data, so it has to be labelled "scheduled". That also brings the shapes/trips adapters and the interpolation logic into scope, so it may be better as a separate play.

The vision and tech stack are ready for this play, so it can go to the Planner.
