● The label is telling you when the estimate was calculated, not when the timetable was fetched. The wording makes it easy to read it the second way.

**What the time in the label is.** In `src/ui/sheet\NearestStopContent.tsx:53-54` the note reads "Positions and times estimated from the timetable at {time}". That time comes from `approaching[0].at`, which is the moment the bus positions and countdowns were last worked out from the current clock. The clock updates every 5 seconds, so the time always shows the current minute.

**Why fetching every 6 hours is enough.** The data is Metro Mondego's published schedule: three static files of about 600 KB each, one per day type (weekdays, Saturday, Sunday). It has no live information, so fetching it every minute would just download the same schedule again. The live part is the calculation: the app takes the current time and works out from the schedule where each bus should be and how long until it reaches your stop.

**A related quirk.** There is a separate "Timetable data from … may be out of date" note that is meant to show when the data was actually fetched. The browser usually hides the header that fetch time is read from (`Date`), so the code falls back to the current time. As a result, that note almost never appears (`documentation/modules/timetable-and-estimates.md:38-41`).
